# コード差分の算定

コード由来の点数は、同じ変更の反復を圧縮した編集量から求めます。
作業時間、難易度、変更の機能上の重要性を推定する指標ではありません。
AI は使いません。

## 編集量

GitHub API のファイル差分から変更前後のトークン列を作り、その差分を編集グループへ分解します。
同じ変更前後のトークン列と重みを持つ編集を、ワークストリーム全体でまとめます。
ファイルや PR が異なっても同じ編集はまとめます。
識別子や文字列の内容は匿名化しません。

編集グループの変更前トークン数を a、変更後を b、出現数を n、重みを w とし、量を次の式で求めます。

    u = w × max(1, max(a, b) / 8) × (1 + 0.25 log₂ n)

通常のコード、テスト、設定、CI の重みは 1、文書は 0.5 です。
グループの量を合計した値を U とします。
同じ編集を 100 回適用した場合の量は、1 回の約 2.66 倍です。
ファイル数の加点とファイル単位の行数上限は使いません。

lockfile、生成コード、出力スナップショットなどは編集量から分離します。
`index.spec.ts-snapshots/` のような Playwright の出力先も生成物です。
生成物が一つでもあればワークストリーム全体の補助量 G を 1、なければ 0 とします。
生成物の枚数や行数によって補助量は増えません。
フルAI実装リポジトリの変更ファイルはすべて生成物として扱います。

## 重要度と配分

リポジトリ数を R、Conventional Commits 補正を C として、重要度を求めます。

    I = min(15, 1 + 1.5 log₂(1 + (U + G) / 10) + log₂ R + C)

係数は暫定値で、実際の貢献度から校正したものではありません。
リポジトリ数とタイトルの補正、レビュー保証、PR の状態、AI・Bot の扱い、各配分枠の割合はコード編集量とは別の条件です。

各編集グループの量を、その編集が各 PR に現れる回数に比例して配分します。
生成物の補助量は、生成物を持つ PR 間で均等に配分します。
この寄与量の比率を、PR 作成枠、実装枠、関連 Issue から各 PR への経路に使います。
PR ごとに定数や対数を加え直しません。
総編集量と補助量がともにゼロの場合に限り、基礎重要度を配分するため PR 間の比率を均等にします。

関連 Issue のない PR は別ワークストリームになるため、PR 分割の影響をこの式だけですべて取り除くことはできません。
未測定の変更量は推測せず、測定できた部分と生成物の補助量から計算します。
したがって未測定を含む PR の点数は、その変更全体を測定した結果ではありません。

## 記録と制約

通常の編集、反復による圧縮、生成物、未測定を区別して確認できるようにします。
バイナリー、欠落・打ち切りのある差分、解析に対応できない差分は未測定です。
測定結果がゼロのファイルと未測定のファイルは別の状態で保存します。
公開データにはファイル統計と編集グループのハッシュ、トークン数、出現数、重みを保存し、差分本文やトークン列を含めません。

算定は字句差分による近似です。
コードの再インデントや意味を持たない空白を除外します。
文字列内の空白、Python・YAML のインデント、Shell・CSS の空白、JavaScript などの改行は保守的に残します。
文書はコードとは別に字句化し、URL の `//` や文章の引用符をコードのコメント・文字列として解釈しません。
ツールの挙動を変えるコメントを消さないため、コメントは一律に除外しません。
完全な構文解析、ファイルをまたぐ移動の検出、参照先やスコープの解決、日本語の形態素解析は行いません。
Vue・Astro の複合構文や差分に含まれない文脈の影響も、完全には判定できません。
差分の区切りによって編集グループのまとまりが変わる場合もあるため、すべての PR 分割に対して値が不変になるとは限りません。

実データによる比較は [編集量スコアの検証](編集量スコアの検証.md) にまとめています。
