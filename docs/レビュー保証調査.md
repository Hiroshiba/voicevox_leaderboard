# 実装点へレビュー保証を反映するための調査

調査日は2026年8月6日です。
VOICEVOXのマージ済みPRと、コードレビューやAI支援貢献を扱う外部の前例を確認しました。

## VOICEVOXのマージ済みPR

GitHub GraphQL APIで、2025年8月1日から2026年8月6日までにVOICEVOX Organizationの公開かつ非アーカイブなリポジトリでマージされた、人間作成の606件のPRを調べました。
作者、マージ者、レビュー状態、追加行、削除行、変更ファイル数を取得し、作者自身とBotによるレビューを除外しました。
各PRの直近100レビューを取得しました。
期間内の最大レビュー数は77件だったため、レビューの欠落はありません。

## 外部の前例

[OpenSSF ScorecardのCode-Reviewチェック][1]は、直近の変更に承認があるか、マージ者がコミット者と異なるかを調べます。
後者は暗黙のレビューとして扱われます。
人間の変更に未レビューが一つあれば10点中7点、複数あればさらに3点を減らします。
AIを含むBotのレビューは、変更を理解する二人目の人間がいる保証にならないため数えません。

[OpenSSF ScorecardのBranch-Protectionチェック][2]は、1人以上の承認を10点中6点へ到達する条件にしています。
2人以上の承認とコードオーナーのレビューは9点へ到達する条件です。
最新の変更を承認することと古い承認を無効にすることは10点へ到達する条件です。

[Linux kernel][3]、[Fedora][4]、[Rocky Linux][5]、[Trusted Firmware][6]は、AI利用の一律減点より、利用の開示と人間による理解、確認、最終責任を重視しています。
[Drupal][7]は、人間によるレビュー、編集、テストを欠くAI生成物を貢献クレジットの濫用として扱います。

これらの前例に共通するのは、AI利用の推定ではなく、独立した人間の確認や投稿者の責任を評価している点です。

## 採点へ反映する条件

PRごとに次の順でレビュー保証を判定します。

1. 作者と共同作者以外の人間による承認があれば、承認済みとします。
2. 作者と共同作者以外の人間による実質的な総評かレビュースレッドがあれば、実質レビュー済みとします。
3. 作者と共同作者以外の人間がマージしていれば、独立マージ済みとします。
4. いずれにも該当しなければ、独立した品質確認なしとします。

承認済み、実質レビュー済み、独立マージ済みのPRは、実装枠を全量配分します。
独立した品質確認がないPRは、実装枠の50%を作者と共同作者へ配分し、残りを未配分にします。

50%はプロトタイプで検証する初期値です。
マージ済みの成果を0点にはせず、独立確認された実装との差も明確にする中間値として選びます。
減らした点を他のPRや人物へ移さないことで、未レビューPRが同じワークストリームの別の実装者を利することも防ぎます。

変更規模は既存の対数式と上限で引き続き評価します。
小さなセルフマージは規模によって元の重要度が低くなり、大規模な未レビュー実装は実装枠の半分が未配分になります。
レビュー点とIssue・調査点は変更しません。

AI関連語は判定条件にしません。
Bot作者は従来どおり実装点を受け取らず、Botレビューもレビュー保証へ数えません。
