# OSS貢献者ランキング／貢献可視化の前例調査

**調査時点：2026年7月24日**

公式ドキュメント、公式ダッシュボード、公開ソースコードを優先して確認した。現在提供されているサービスと、過去に公開された実装例、OSS以外の隣接分野は区別している。

以下は前例の調査結果であり、VOICEVOX向けの指標案や推奨は含めていない。

## 全体像

確認できた方式は、大きく次のように分かれていた。

| 方式                   | 実例                                                           |
| -------------------- | ------------------------------------------------------------ |
| 単一活動の件数順位            | GitHub Contributors                                          |
| 活動種別ごとの列別順位          | GitLab Contribution Analytics、Rocket.Chat、Pull Request Stats |
| 複数活動の合計件数            | CNCF DevStats、LFX Insights                                   |
| 活動ごとの重み付き合計          | GitHub Dashing、Drupal Marketplace                            |
| 貢献関係をグラフ化した影響度       | OpenRank、SourceCred                                          |
| 比率による順位              | PR Game                                                      |
| 複数部門・ロール・称号          | elizaOS、HackerOne、Kaggle                                     |
| 点数化せず、貢献種別だけを表示      | All Contributors、CHAOSS、GrimoireLab                          |
| 個人を順位付けせず、組織のみ順位付け   | Drupal Marketplace、OSCI                                      |
| AI利用をランキングと別系統で集計    | LFX AI Code Tracker                                          |
| AI利用を開示・責任・不正対策として扱う | Linux、Fedora、Rocky Linux、Trusted Firmware、Drupal             |

# 1. OSSにおける直接的なランキング・スコアリング

## 1. GitHub Contributors graph

| 項目            | 調査結果                                                                                |
| ------------- | ----------------------------------------------------------------------------------- |
| 種別            | GitHub標準機能                                                                          |
| 順位対象          | 単一リポジトリのコントリビューター上位100人                                                             |
| 基本指標          | コミット貢献数                                                                             |
| 集計条件          | デフォルトブランチに到達しているコミットが対象。マージコミットと空コミットは除外される。コミットのメールアドレスがGitHubアカウントに関連付けられている必要がある |

| 表示・出力         | グラフ、表形式、CSV、PNG                                                                     |
| Issue・PR・レビュー | Contributors順位には含まれない                                                               |

| 補足            | GitHub Insightsの一部機能には、コミット数が非常に多いリポジトリで利用制限がある                                     |

GitHubの標準的な前例は、異種活動を混ぜず、デフォルトブランチに入ったコミットだけを数える方式である。 ([GitHub Docs][1])

## 2. GitLab Contribution analytics

| 項目            | 調査結果                                                                |
| ------------- | ------------------------------------------------------------------- |
| 種別            | GitLabのグループ分析機能                                                     |
| 順位対象          | グループメンバー                                                            |
| 活動種別          | Push、Issue、Merge Request                                            |
| 集計方法          | 各活動を別々の列として表示し、列ごとに並べ替える                                            |
| 期間            | 直近1週間、1か月、3か月                                                       |
| コミットの扱い       | 一意なコミットSHAではなくPushイベントを集計                                           |
| Pushイベントを使う理由 | 同じコミットを別ブランチへPushすると重複計上され得ることを認識したうえで、GitLab上の貢献イベントとしてPushを使用している |
| レビュー・コメント     | 主要な表示列はPush、Issue、Merge Request。レビューやコメントをまとめた単一総合点ではない             |
| 提供プラン         | Premium、Ultimate                                                    |
| AI・Botの扱い     | AI利用による区別は公開仕様にない                                                   |

GitLabのドキュメントは、3個の一意なコミットのうち2個を別ブランチにもPushした場合、5件として記録される例まで明示している。つまり、コード成果物の一意性より、プラットフォーム上の活動イベントを数える設計である。 ([GitLab Docs][2])

| 項目                  | 調査結果                                                                                                 |
| ------------------- | ---------------------------------------------------------------------------------------------------- |
| 種別                  | CNCFが公開しているOSS活動分析基盤                                                                                 |
| 順位対象                | 個人、企業、国、リポジトリなど、ダッシュボードごとに異なる                                                                        |
| 総合指標「Contributions」 | 対象となるGitHubイベントの一意なイベントID数                                                                           |
| 総合指標に含まれるイベント       | Push、Pull Request、Issue、Pull Request Review、Commit Comment、Issue Comment、Pull Request Review Comment |
| コミット指標              | 総合指標とは別に、一意なコミットSHA数として集計                                                                            |
| その他の個別指標            | Issue、PR、マージ済みPR、レビュー、コメント、Push、アクティブリポジトリなど                                                         |
| Botの扱い              | クエリ上でBotを除外する仕組みを持つ                                                                                  |
| 重み付け                | 「Contributions」は、公開SQL上では対象イベントを異なる重みで評価する式ではなく、イベントIDを数える構成                                         |
| 展開範囲                | CNCF外の公開GitHubプロジェクトでも利用できるOSS基盤として公開されている                                                           |
| AIの扱い               | AI利用の有無は総合指標の係数になっていない                                                                               |

特徴的なのは、コミットを独立指標として残しながら、Issue、PR、レビュー、コメント等を「Contributions」という別の総活動量にまとめている点である。PushイベントとコミットSHAは別の概念として扱われる。 ([GitHub][3])

## 5. OpenDigger OpenRank

OpenRankには、コミュニティ単位で計算する方式と、GitHub全体を対象とした月次方式がある。

| 項目                     | 調査結果                                                  |
| ---------------------- | ----------------------------------------------------- |
| 種別                     | 開発者とリポジトリの関係をグラフとして評価するアルゴリズム                         |
| 単純件数との違い               | IssueやPRの件数を直接合計するのではなく、参加者、Issue／PR、リポジトリ間で影響度を伝播させる |
| Community OpenRankの初期値 | 開発者・リポジトリ1.0、Issue 2.0、未マージPR 3.0、マージ済みPR 5.0         |
| Issue／PR内での配分          | 作成者であるInitiateに初期値の50％を配り、残りを参加者に配分                   |
| 活動ウェイトの例               | Initiate 2、Comment 1、Review 1、Close 2                 |
| リアクション                 | リアクションの種類を複数カテゴリに分け、異なる重みを設定                          |
| 履歴                     | 過去のOpenRankを一部継承し、減衰させる                               |
| Global OpenRank        | 月ごとに開発者とリポジトリの活動グラフを作り、前月値を継承・減衰させる                   |
| Global版の月次減衰           | 公開アルゴリズムでは0.85                                        |
| 表示                     | アカウントごとのOpenRankと、貢献元・比率・値の内訳を表示できる                   |
| AI・Bot                 | AI支援かどうかは計算式に含まれない                                    |

件数の多い人をそのまま上位にする方式ではなく、「誰が、どのIssue・PR・リポジトリに関わったか」というネットワーク構造を順位へ変換する前例である。 ([OpenDigger][5])

## 6. SourceCred

| 項目          | 調査結果                                                                |
| ----------- | ------------------------------------------------------------------- |
| 種別          | コミュニティ活動をグラフ化してCredを計算するOSS                                         |
| 主な入力元       | GitHub、Discord、Discourse、コミュニティ独自のInitiative                        |
| GitHub上のノード | Issue、PR、レビュー、コメント、コミット、ユーザー、Bot                                    |
| 主アルゴリズム1    | CredRank。PageRank系のグラフアルゴリズムで、コミュニティ全履歴を一つの設定で計算する                  |
| 主アルゴリズム2    | CredEquate。活動を木構造／代数的モデルで評価し、期間ごとに設定を変更できる                          |
| 重み付け        | PR作成者、コミット作成者、レビュー作成者、リアクション等のウェイトを設定可能                             |
| 複数著者        | 複数人が著者として関連付けられた場合、Credを均等分割できる                                     |
| Bot         | 明示的なBotリストを持ち、順位や報酬分配から除外できる                                        |
| 時間処理        | 週ごとのCred平滑化や、即時重視・均衡・直近重視などの減衰ポリシー                                  |
| 報酬との連携      | Credを基に、週次でGrainと呼ばれる報酬・配分単位を分配できる                                  |
| 公開文書上の注意    | デフォルトではマージ済みPRを同程度に評価する部分があり、規模や信頼関係によっては品質より量を増やす誘因になると文書自身が警告している |
| 開発状況        | GitHubプラグインはBeta、CredEquateはAlphaと記載                                |
| AI          | AI利用の有無は標準計算項目にない                                                   |

SourceCredは、コード量だけでなくレビュー、コメント、コミュニティでの関係性を含め、設定可能なグラフスコアに変換する前例である。同時に、スコアを報酬へ接続した場合のゲーミングについて、公式文書が明示的に注意している。 ([sourcecred.io][6])

## 7. Drupal Contribution Credit／Marketplace Ranking

Drupalでは、**個人の貢献認定**と**組織のランキング**が分離されている。

| 項目                 | 調査結果                                                                                 |
| ------------------ | ------------------------------------------------------------------------------------ |
| 個人                 | 個人には貢献クレジットを表示するが、個人ランキングは行わない                                                       |
| 個人ランキングを行わない理由     | 可処分時間、雇用環境、経済状況などの特権を反映しやすく、個人間競争を不健全にするという説明                                        |
| 組織                 | Drupal Marketplaceでは、組織を重み付き貢献クレジットで順位付け                                             |
| Issueクレジット         | 一つのIssueについて複数人・複数組織へ付与可能                                                            |
| コメント               | Issueに書き込んだだけで自動的に全員へ付くのではなく、メンテナーが実質的に貢献したコメントを選ぶ                                   |
| 非コード貢献             | ドキュメント、会議参加、講演、セキュリティレビュー、企画などもクレジット対象になり得る                                          |
| プロジェクト重要度          | プロジェクトの利用規模などに応じ、Issueクレジットへ1～10の係数。最低値は1                                            |
| Case study         | Drupal 11は10、Drupal 10は7、Drupal 9は5として記載。これらのクレジットには期限がない                            |
| 組織メンバーシップ          | 財政支援規模に比例したクレジット。Ripple Maker従業員1人につき追加のstanding credit 1                            |
| Contributor role支援 | 組織が特定貢献者の役割を支援した場合、範囲と時間に比例して評価。Issueとの重複二重計上は行わない                                   |
| イベント支援             | 直近12か月について、DrupalCon 220、Camp／Fest 50、Meetup・Contribution Event・外部イベント25など           |
| 個人会員               | 小規模だが継続的な加点                                                                          |
| 期間上の文書差異           | 現行ページには「直近12か月のIssue credits」という見出しと、「Marketplaceでは直近90日で修正されたIssueを数える」という記述が併存している |
| AI生成物              | AI生成コード・文章を開示しない、または人間のレビュー・編集・テストなしで提出する行為をクレジット濫用として規定                             |
| 自動投稿               | 許可されていない大量の自動Issue・コメント投稿も濫用                                                         |
| 制裁                 | クレジット取消、負のクレジット、Marketplaceからの一時除外など                                                 |

Drupalは、個人に順位を付けず、組織には金銭支援、イベント支援、Issue解決、役割支援などを統合した重み付き順位を付ける前例である。また、今回確認した中では、AI生成物によるクレジット稼ぎを最も明示的に規制している。 ([Drupal.org][7])

## 10. OpenSauced OSCR

| 項目                     | 調査結果                                                     |
| ---------------------- | -------------------------------------------------------- |
| 正式名称                   | Open Source Contributor Rating                           |
| 種別                     | 個人のOSS貢献レーティング                                           |
| 最大値                    | 300                                                      |
| 期間                     | ローリング90日                                                 |
| 意味                     | 生涯累積ではなく、現在の貢献状態を表すスナップショット                              |
| 構成要素                   | 貢献品質、Contributor Confidence、Sway                         |
| Contributor Confidence | リポジトリをStar／Forkした人が、その後コントリビューターになる可能性。ForkはStarより強く扱われる |
| Sway                   | 会話や活動を動かす能力として説明される                                      |
| 関連指標                   | 30日間のPR数によるActivity分類、Activity Ratio、Lottery Factorなど    |
| Activity分類             | 30日間のPRが80超でHigh、5～80でMedium、5未満でLow                     |
| Lottery Factor         | PRの50％を2人以下が担う場合など、少人数依存を示す                              |
| 式の公開度                  | 300点のうち各構成要素へ何点を割り当てるかという完全な数式は、確認した公開Glossaryには示されていない  |
| AI                     | AI利用の有無を直接評価する説明はない                                      |

OSCRは、単純な活動件数ではなく、直近90日の品質、継続参加可能性、影響力をまとめたレーティングとして説明されている。 ([GitHub][10])

## 11. GitHub Dashing

| 項目        | 調査結果                                                                    |
| --------- | ----------------------------------------------------------------------- |
| 種別        | 複数GitHubリポジトリを集計する公開ダッシュボード実装                                           |
| 主な利用例     | SilverStripe向けに公開された実装                                                  |
| 期間        | 直近30日                                                                   |
| 目的        | 短期間の相対的な活動を表示し、新しいコントリビューターも上位へ入り得るようにする                                |
| デフォルト重みの例 | Issue作成5、Issue終了5、PR作成10、PR終了5、PRコメント1、Issueコメント1、Commitコメント1、Commit 20 |
| コード量      | 追加行・削除行を扱う設定もある                                                         |
| 大規模変更対策   | サードパーティコードや巨大な一括変更が過度な得点にならないよう、追加・削除行数の上限や閾値を設定可能                      |
| ブランチ      | デフォルトブランチを対象                                                            |
| メンバー除外    | Organizationメンバーを除外し、外部コントリビューターだけに絞る設定が可能                              |
| AI・Bot    | AI利用の識別はない                                                              |
| 現在性       | 現在の標準サービスではなく、公開実装としての前例                                                |

異なる活動へ明示的な整数ウェイトを付け、合算する前例である。コミット1件が20点、PR作成が10点、コメントが1点というように、設定値がそのまま公開されている。 ([GitHub][11])

## 12. PR Game

| 項目    | 調査結果                                    |
| ----- | --------------------------------------- |
| 種別    | コードレビュー促進を目的としたLeaderboard実装            |
| 基本式   | レビューしたPR数 ÷ 自分が作成したPR数                  |
| 順位の意味 | コードを提出するだけでなく、他者のPRをどの程度レビューしたか         |
| 掲載条件  | スコアが1未満のユーザーはLeaderboardに掲載しない          |
| 匿名性   | 未認証画面では名前をランダム化できる                      |
| 報酬    | Ethereumによる報酬連携のオプション                   |
| 代替式   | READMEでは、コメント長やレビュー所要時間などへ式を変更できることにも言及 |
| 状況    | 小規模な公開実装・概念実証に近い                        |
| AI    | AI利用は扱わない                               |

これは総活動量ではなく、「レビュー数を自分のPR作成数で割る」という比率を順位にした前例である。 ([GitHub][12])

# 4. AI支援による貢献を扱う前例

今回確認した公開仕様では、AI利用の有無をそのまま個人ランキングの加点・減点係数にした主要な前例は確認できなかった。実際には、次の四つの扱いが中心だった。

1. AI利用の開示
2. 人間による最終責任
3. 大量投稿・未検証生成物の不正利用規制
4. Contributor rankingとは別のAI統計

## AI関連前例の比較

| 前例                        | AI支援の扱い                                                                | 開示方法                                                  | ランキング・クレジットとの関係                                                                                          |
| ------------------------- | ---------------------------------------------------------------------- | ----------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| Linux kernel              | AIエージェント自身はDCOの`Signed-off-by`を付けられない。人間がコード、ライセンス、動作を確認し、自ら署名して全責任を負う | `Assisted-by: AGENT_NAME:MODEL_VERSION`。必要に応じてツールも記載  | AI利用を点数化しない。責任主体と生成支援をコミットメタデータで分離する ([Kernel Documentation][25])                                        |
| Fedora                    | AI出力は提案として扱い、投稿者が理解・レビュー・テストして責任を持つ。AIによる最終的な採否判断を認めない                 | `Assisted-by:`等による透明性を推奨                              | CoC、資金配分、講演採否、リーダー選定など、人の地位に関する評価をAI／MLに行わせない ([Fedora Community Blog][26])                              |
| Rocky Linux Documentation | AIの大部分をほぼ無変更で採用した場合は開示必須。文法・スペル・明瞭化だけなら必須でない                           | Gitでは`Assisted-by:`、文書では`ai-contributors` frontmatter | AIを人のコミュニティ上の地位、資金、リーダーシップ、CoC等の最終評価者にしない。AI利用自体は得点化しない ([Rocky Linux Docs][27])                         |
| Trusted Firmware          | AI支援貢献を受け入れるが、投稿者がツール規約、著作権、ライセンス、第三者権利を確認する                           | Linux kernelに倣った`Assisted-by:`トレーラー                   | AI利用による順位補正はない。開示と法的責任を扱う ([trustedfirmware.org][28])                                                    |
| Drupal                    | 未開示のAI生成物、または人間のレビュー・編集・テストを欠くAI生成物をクレジット濫用と規定。許可のない自動大量投稿も濫用          | 開示と人間による実質確認を要求                                       | AI利用そのものへの一律減点ではなく、不正なクレジット取得として取消、負のクレジット、組織の一時除外等を適用 ([Drupal.org][29])                                |
| LFX AI Code Tracker       | 重要OSSプロジェクトのAIコーディングツール利用を追跡                                           | 使用ツール別のAI-assisted commitsを表示                         | 過去12か月のAI支援コミット数と割合を、Contributor Leaderboardとは別画面で表示。確認した公開ページには判定・検出方法の詳細は掲載されていない ([LFX Insights][30]) |

# 6. 調査結果の要約

今回確認した前例から、事実として次の傾向が確認できる。

| 観察項目      | 確認結果                                                                                      |
| --------- | ----------------------------------------------------------------------------------------- |
| 一つの総合順位   | 存在するが、コミットのみ、イベント合計、固定ウェイト、グラフスコア、レーティングなど、計算方法は大きく異なる                                    |
| 複数部門      | 活動種別ごとの列、専門クラス、期間別順位、新規参加者部門などの前例が多数ある                                                    |
| Issue報告   | 単純件数、総活動への加算、メンテナー認定、第三者による妥当性評価、非数値ラベルなど、扱いが分かれる                                         |
| レビュー      | 単純件数だけでなく、応答時間、レビュー対象量、コメント数、PR作成数との比率などが使われている                                           |
| 非コード貢献    | LFX、Drupal、All Contributors、CHAOSSなどが、文書、議論、イベント、支援、コミュニティ活動を明示的に扱う                       |
| 個人と組織     | Drupalのように個人順位を意図的に作らず、組織だけを順位付けする例がある。OSCIも組織順位のみ                                        |
| AI支援      | 今回確認した公開ランキング式では、AI利用を直接の加点・減点係数とする例は確認できなかった                                             |
| AIの実際の扱い  | 開示、人間の最終責任、未検証生成物や大量投稿の濫用規制、ランキングと別のAI統計という形が中心                                           |
| 数式の公開度    | OpenRank、GitHub Dashing、PR Gameのように式を詳しく公開する例と、elizaOS、OSCRのように構成要素のみ公開し完全なウェイトを公開しない例がある |
| ゲーミングへの言及 | DrupalとSourceCredは、指標を目的化した低品質投稿や量的インセンティブの問題を公式文書で明示している                                 |

特にAIについては、**「AIを使った人／使わなかった人」を同じランキング式の中で直接補正する方式より、AI支援の開示、投稿者本人の責任、Bot・大量投稿の除外、不正クレジットの取消、AI活動の別ダッシュボード化として扱う前例が中心**だった。 ([Kernel Documentation][25])
